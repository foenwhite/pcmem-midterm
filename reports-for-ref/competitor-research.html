摘要：五个选题各自的"已经有人做了"和"还没人做"

  1. 选题 1（PC 文件记忆）——采集层已商品化（Recall、screenpipe），检索层已成熟（Khoj、AnythingLLM），但"项目 / 版本 / 引用"关系没有任何一个系统显式建模。可做的差异化：项目级本体 + 双时间轴的版本演化链。
  2. 选题 2（多源消息官）——聚合、去重、摘要、排序全部有成熟产品（Folo、Horizon、Kagi News、Feedly Leo、GDELT）。空白在于"面向个人的、持续更新的实体-事件图"，以及"旧结论被新证据推翻"的状态更新（GDELT 是世界的图，不是"我的图"）。
  3. 选题 3（项目考古学家）——2026 年"代码知识图谱"这一波（graphify 126k★、codegraph 74k★）已经把当前代码快照的图做透了；时间维度几乎无人触及：没有跨版本的时序知识、没有"为什么改成这样"的动机抽取。这是最清晰的空白，也是最值得选的题。
  4. 选题 4（个人数字人）——风格克隆（WeClone）、记忆写入（mem0/memU）、手动图谱（Logseq）都很成熟。缺"经历/事件"的统一表示、跨源同一事件的对齐，以及长期一致性与遗忘机制；而且明星产品 Rewind/Limitless 已于 2025-12-19 关停，正说明"只记录不结构化"不可持续。
  5. 选题 5（股票量化情报）——数据、LLM、Agent、回测全都有强对手（OpenBB 74k★、TradingAgents 111k★、qlib 49k★、KAG 9k★）。空白是"公司-产业-供应链-事件"融成持续更新知识网络并公开可复现的系统，以及事件与行情的 point-in-time 对齐（未来信息泄露）与"跨公司影响路径"的可解释性评测。

重要提示：本报告列举的绝大多数项目 ○ 并不使用知识图谱——这既是威胁（"不用图谱也能做"），也正是课程项目要论证的对照面。凡是标注 ● / ◐ 的，都是可以直接拿来当技术底座或 baseline 的。

第 0 组 · 跨选题通用底座（记忆 / 图 RAG / 图数据库）

这 10 个不是"竞品"，而是五个选题都可能共用的技术底座。先定底座，再谈选题，能省掉一半重复调研。

microsoft/graphrag ★ 36,323更新 2026-10-12● 有 KG

微软开源的"图式 RAG"框架：先用 LLM 从语料中抽取实体与关系，再做社区聚类生成"社区摘要"；查询时提供局部（实体邻域）与全局（主题摘要）两种检索粒度。它是"显式知识表示 vs 向量 RAG"最常被引用的公开对照基线。

对本项目：几乎任何选题的"对比实验"都要拿它当 baseline（局部/全局查询的差别正好对应"多跳推理"和"跨来源概括"）。已知短板：构建成本高、增量更新弱——这正是你可以发力的地方。

HKUDS/LightRAG ★ 40,111更新 2026-10-12● 有 KG

双层级图索引（低层实体 / 高层主题）+ 增量插入，声称在 token 成本与构建速度上显著优于 GraphRAG，并支持新数据持续入库（EMNLP 2025）。

对本项目：选题 1/2/3 都要求"持续更新已有知识"，LightRAG 的增量图索引是现成解法；把它与 GraphRAG 的"重建式"更新做对照，本身就是一组很好的实验。

getzep/graphiti ★ 31,702更新 2026-10-13● 有 KG

面向 Agent 的时序知识图谱：把对话/事件作为 episode 写入，自动抽取实体与关系，并维护双时间轴（事件真实发生时间 vs 系统录入时间），支持"某时刻的事实快照"、失效与矛盾检测。

对本项目：课程难点里的"版本关系""时间关系""过期信息处理""旧信息被新信息推翻"——graphiti 是唯一把这些当作一等公民的开源底座。选题 1/2/5 都建议直接基于它做。

mem0ai/mem0 ★ 67,107更新 2026-10-12◐ 混合

事实抽取式长期记忆层：从对话中抽取"记忆条目"，做去重、冲突更新与用户级隔离，向量库为主、图存储可选（graph memory）。是工业界集成最广的记忆中间件。

对本项目：这是"最省事的记忆方案"，也是你必须超越的 baseline——它只做"条目级"抽取与检索，没有本体、没有项目/事件层级、没有显式的跨实体推理。

letta-ai/letta（MemGPT） ★ 25,121更新 2026-09-10◐ 混合

把 LLM 上下文当"内存"、外部存储当"磁盘"的有状态 Agent 框架：Agent 自己管理记忆的分页、换出与检索，强调长期记忆与自我改进。

对本项目：它解决了"何时写入/何时调出记忆"这一调度问题（选题 4 明确问到"Agent 应该在什么情况下主动调用哪些记忆"），但记忆本身是自由文本块，无显式结构。

topoteretes/cognee ★ 32,158更新 2026-10-13● 有 KG

ECL（Extract–Cognify–Load）流水线：把文档与对话转成统一的"记忆图 + 向量"，用同一次查询同时打图与向量，主打小模型本地运行、零成本起步。

对本项目：它的三层记忆分层（会话/知识/图）与"统一查询接口"值得直接抄工程结构；开源可自托管，适合做小型演示系统。

infiniflow/ragflow ★ 92,146更新 2026-10-13◐ 混合

端到端 RAG 引擎：自研 DeepDoc 文档理解（版面分析、表格识别）+ 分块检索 + 可选的实体/关系抽取（Knowledge Graph 模式），工程完成度极高。

对本项目：选题 1（异构文件解析）与选题 5（公告/财报解析）可以把它当"摄取层"直接用；但它默认不维护跨文档、跨时间的实体链接。

FalkorDB/FalkorDB ★ 9,492更新 2026-10-13● 有 KG

基于 GraphBLAS 稀疏矩阵的高性能图数据库，定位就是"给 LLM 用的知识图谱"（GraphRAG），提供多跳查询与向量检索的组合。

对本项目：若自建本体与图 schema，比 Neo4j 更轻、更快接入 GraphRAG 生态；Neo4j + Cypher 仍是教学最常规的选择（见选题 5 的教程类项目）。

HelixDB/helix-db ★ 6,198更新 2026-10-12● 有 KG

Rust 实现、跑在对象存储上的 OLTP 图数据库，原生内置向量与全文索引（"图 + 向量 + 文本"一套引擎）。

对本项目：适合作为"混合检索"的存储层选型；相比需要自己拼接 Neo4j + FAISS 的方案，部署与一致性成本更低。

open-webui/open-webui ★ 155,533更新 2026-10-13○ 无 KG

最流行的自托管 LLM 交互外壳：多模型接入、知识库上传、RAG、工具调用与权限管理。

对本项目：报告要求"原型系统（demo 展示）"，它是成本最低的 demo 外壳——把 RAG 换掉、接上你自己的图谱服务即可，不用把力气花在前端。

选题 1 · 帮助 Agent 的全 PC 文件管理记忆系统

题目要点：文件分散、多版本、跨目录；目录+文件名已不够；普通语义检索只会"找相似"；要求回答"属于哪个项目 / 哪个是最新版 / 以前做过类似的事"。

先把赛道分层再调研：采集层（截图/OCR）→ 解析层 → 记忆存储层 → 关系推理层 → 交互层。 结论：前四层都有强对手，第五层（项目/版本/引用关系的推理）基本空缺。

采集与"电脑历史"

screenpipe（原 mediar-ai） ★ 21,930更新 2026-10-13○ 无 KG

7×24 本地录制屏幕与麦克风，OCR + 转写后建成本地可检索的"电脑历史"，主打把个人工作上下文喂给 AI Agent，现已商业化（YC S26，网站 screenpi.pe）。

对本选题：证明"采集层已商品化、且正在被 Agent 生态吸收"。你在采集上不可能赢它，差异化只能放在它没做的结构化记忆与关系推理。

openrecall/openrecall ★ 2,957更新 2025-09-24○ 无 KG

开源版 Windows Recall：定时截屏 + OCR + 本地向量检索，主打"隐私优先的回忆录"。

对本选题：已近一年停更，恰好说明"截图 + 向量相似度"这条路线缺乏长期价值——只解决"找到相似画面"，不解决任何关系问题。

Microsoft Recall（Windows 内置） 非 GitHub · 不受门槛限制○ 无 KG

Copilot+ PC 的系统级功能：持续快照屏幕，建立语义索引，支持自然语言回找"我什么时候看过这个"；历经多次延期与隐私争议，自 2025 年底起正式可用，支持加密、卸载与按应用/站点过滤。

对本选题：系统级对手，必须引用。它只做"快照检索"，不理解项目、版本、引用关系——这是你论证"结构化知识带来增量价值"的最强参照。

记忆层：从"条目"到"结构化"

多智能体个人助手：持续捕获屏幕活动，按记忆类型分层固化（episodic / semantic / procedural / resource / knowledge vault），再由不同 Agent 分别负责检索、反思与固化。

对本选题：与"从文件搜索升级为理解长期工作历史"高度同构，而且免费给了你一套记忆类型学（哪些是事实、哪些是流程、哪些是资源）——可以直接借来做本体设计。

basicmachines-co/basic-memory ★ 4,162更新 2026-10-12● 有 KG

"让 AI 对话真正记住你"：把 Markdown 笔记解析成由 observation（观察）与 relation（关系）构成的本地知识图谱，支持正向/反向链接遍历、按项目组织，通过 MCP 暴露给 Agent。

对本选题：刻意不用黑盒向量——所有知识都是人可读、可 diff、可版本控制的 Markdown。这是"最小可行知识图谱"的最佳模板，也是你论证"显式表示可维护性"的现成证据。

microsoft/kernel-memory ★ 2,232更新 2026-06-08◐ 混合

面向"用户 / 团队 / 应用"三个层级的记忆方案：文档管道（摄取→分块→嵌入）+ 记忆存储（向量 + 可选图）+ 检索编排，含完整的分层架构与 API。

对本选题：它的"用户级 vs 团队级记忆"分层，直接对应"个人文件空间 vs 项目空间"的双层组织方式，值得在 schema 里体现。

文件检索与"第二大脑"

khoj-ai/khoj ★ 37,669更新 2026-08-02○ 无 KG

"个人第二大脑"：把本地文档与网页索引成语义检索库，提供对话式问答，可自托管、可接任意在线/本地 LLM，并支持定时自动化与研究任务。

对本选题：这是"个人文件问答"这一层最成熟的开源实现，直接当 baseline。它的短板正是你的题眼：只有文档级相似度，没有项目、版本、引用之间的多跳关系。

Mintplex-Labs/anything-llm ★ 67,021更新 2026-10-12○ 无 KG

本地优先的桌面 LLM 工作台：多模型、文档工作区（把一批文件夹做成可对话知识库）、Agent 与工具调用、向量/全文双检索。

对本选题：可作为 demo 外壳或 baseline；它处理"一批文档"，但不处理"一个项目的长期演化"。

reorproject/reor ★ 8,543更新 2025-05-13◐ 混合

本地 AI 笔记应用：本地嵌入模型索引你的笔记，提供"相关笔记图"视图与前向/后向链接，全离线推理、数据不出机器。

对本选题：代表"个人知识管理 + 嵌入"的主流做法，但 2025 年后近乎停更——说明纯向量关联在实践中的粘性有限。

qarmin/czkawka ★ 34,224更新 2026-09-16○ 无 KG

多功能本地文件清理工具：查重复文件、相似图片（感知哈希）、空目录、损坏文件，速度极快。

对本选题：非 LLM 基线。"版本识别"的第一层（完全重复 / 近似重复）已有成熟工具，你的图谱应当建在它之上（文件级 hash/相似度作为证据），而不是重新发明。

Everything / Recoll 非 GitHub · 不受门槛限制○ 无 KG

传统桌面搜索的两个极端：Everything（Windows，文件名瞬时索引，秒级枚举）与 Recoll（Linux/macOS，全文 + 元数据检索，支持插件式语义扩展）。

对本选题：对照组。它们能瞬间回答"哪个文件名匹配"，完全不能回答"哪个是最新版、属于哪个项目"——这是报告引言里最好的对比材料。

竞品空白与选题建议

  • 已被解决：截图/OCR 采集（Recall、screenpipe）、文档问答（Khoj、AnythingLLM 67k★）、相似检索、重复文件检测（czkawka）、单条记忆写入与去重（mem0、cognee）、时序事实（graphiti）。
  • 空白 1：项目级本体缺失。没有任何一个系统把 Project / Deliverable / Version / cites / derives-from / supersedes 建模成一等公民。
  • 空白 2：版本判定是"相似度"而非"演化链"。czkawka 给重复，Khoj 给相似，但"v1→v2→最终版"的有向演化链没人做。
  • 空白 3：无人做遗忘与过期。题目明确问到的"长期记忆更新与遗忘"在所有开源系统里都是缺失项。
  • 空白 4：没有评测集。要证明 KG 比 RAG 好，需要自己造一个"文件→项目→时间"的多跳问答集（可人工标注 50–100 题）。
  • 建议定位：以 graphiti 式双时间轴 + basic-memory 式可读图谱为骨架，自建"文件演化本体"；对照组 = Khoj/AnythingLLM（纯向量）与 czkawka（无 LLM）。

选题 2 · 天才消息官：多源消息收集整理与决策推荐

题目要点：来源多、更新快、重复多、上下文分散；单条消息不重要、多条组合才成趋势；要能回答"发生了什么 / 什么值得关注 / 是否影响决策"。

赛道现状：聚合、去重、摘要、排序全部有成熟产品，且大厂在做（Feedly Leo、Kagi News、Apple 通知摘要）。 唯一的空白是"面向个人的、持续更新的实体-事件图"以及状态更新（旧结论被推翻）——大厂产品都是"世界的图"，不是"我的图"。

聚合与读取端

GDELT Project 非 GitHub · 不受门槛限制● 有 KG

全球新闻事件图谱：把各国新闻自动编码成 CAMEO 事件（actor–action–target + 地点 + 时间 + 语气），每 15 分钟更新一次，提供 BigQuery / API / 原始文件，横跨 65 种语言、二十余年历史。

对本选题："消息 → 结构化事件"的行业标杆，也是现成的外部事件源与 ground truth（可用它校验你的事件聚类质量）。它做的是"世界的事件图"，个人关注方向、决策相关性完全不管——空白正好留给你。

Event Registry 非 GitHub · 不受门槛限制● 有 KG

商业新闻情报 API：自动把同一事件的成百上千篇报道聚类成一个 event，抽取实体（人物/机构/地点/概念）与关系，输出事件摘要、时间线、相似事件与媒体覆盖分析。

对本选题："同一事件识别"这一难点的成熟实现。它的做法（事件聚类 + 实体链接 + 时间线）可以直接作为你的方法参考；但它不下任何"值得关注"的判断，也不建模"证据冲突"。

DIYgod/RSSHub ★ 46,514更新 2026-10-13○ 无 KG

"万物皆可 RSS"：数千条路由把微博、知乎、B 站、公众号、播客、GitHub、arXiv 等没有 RSS 的站点变成标准 feed，配套公共实例与文档。

对本选题：数据源层的现成答案，直接省掉你一半采集工作量。多源异构的你只需要处理"归一化 + 去重 + 事件归并"，而不是每个平台写爬虫。

RSSNext/Folo（Follow） ★ 39,095更新 2026-10-13○ 无 KG

目前最流行的"AI RSS 阅读器"：统一收件箱 + AI 摘要/翻译/分类 + 每日摘要推送，同时支持 RSS 与社交通道，界面体验为同类最好。

对本选题：读取端的产品标杆（体验层面参照物）；但它的"AI"止于摘要与标签，没有事件聚合、没有跨消息推理。

Thysrael/Horizon ★ 9,651更新 2026-10-13○ 无 KG

个人"新闻雷达"：多源抓取 → LLM 打分筛选 → 生成中英双语的每日简报并可直接发布，全流程开源可自托管。

对本选题：与你的"每日/周期简报生成"环节直接对标且可读源码——重点看它的重要性打分与去噪策略，那是你要超越或对标的第一个环节。

FreshRSS ★ 16,280更新 2026-10-12○ 无 KG

成熟的自托管 RSS 聚合器（PHP），支持多用户、标签、全文检索、插件与 API。

对本选题：作为"无 LLM / 无关系"的经典基线：它把消息按 feed 和标签组织，正是题目所述"上下文分散、难以归并"的现状。

miniflux/v2 ★ 9,792更新 2026-10-12○ 无 KG

极简主义 RSS 阅读器（Go 单二进制），API 完善、依赖极少，常被当作自动化管道的上游。

对本选题：工程上最省心的 feed 后端，适合做"消息进来"的第一跳。

DevXDojo/MrRSS ★ 2,588更新 2026-10-13○ 无 KG
