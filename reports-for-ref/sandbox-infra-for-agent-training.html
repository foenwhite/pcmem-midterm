调研报告 · pj01 选题 1 · PC-Mem

为 Agent 后训练而生的大规模沙箱基础设施：我们能借什么，不要借什么

面向一个「137 个文件、11 道 QA、没有 GPU 集群」的课程项目，重读 2025–2026 年的 agent 环境基建。报告写作时间：2026 年 11 月。

结论先行（5 行内）

① 2026 年的沙箱热不是为了「安全地跑代码」，而是为了让 reward 可从环境状态里读出来：每个优化步要上千个可重置、可并行、状态干净、全程留痕的环境。

② 那套东西的规模（K8s + 微虚机 + rollout 调度）我们用不上；但它的契约（只读语料 + 可写覆盖层 + 固定时钟 + 网络策略 + verifier + 轨迹落盘）几乎可以 1:1 抄进一个 docker run。

③ 对我们收益最大的三件事是：每语料一个只读容器、每次运行一个 manifest（可复现指纹）、verifier 钩子 + 证据落盘。microVM / K8s / 托管 sandbox API 明确不借。

1. 为什么 2026 年突然需要「沙箱基础设施」

结论：因为「环境」从评测的附庸变成了训练数据的生产设备。当 agent 的后训练靠 RL / rejection sampling 时，环境不再是「跑一次评测的场地」，而是「每个优化步都要吐出成千条轨迹的工厂」。工厂的瓶颈不在模型，而在 CPU 侧的容器生命周期。下面五条是驱动因素，逐条标注证据强度。

1.1 五个驱动因素

  1. Reward 必须从环境状态读出来，而不是从文本里猜。 主流环境把「任务是否完成」定义为对系统最终状态的检查：AndroidWorld 的 evaluator 直接查 SQLite 表里新增/删除的行，而不是比对截图；MCPMark 每个任务带一个确定性 Python 验证脚本，跑完检查最终环境状态并重置环境。直接证据 这条对我们最有用：QA 的分数也应该来自对图谱/文件系统的断言，而不是「模型说完成了」。
  2. 并行 rollout 的瓶颈从 GPU 转移到了 CPU 沙箱的冷启动。 Google Cloud 在 2026-09 发布 GKE Agent Sandbox 时的官方说法是：GPU 集群空转、等待「数分钟」的 CPU 沙箱冷启动，加上数千次几 GB 级的 SWE-bench 风格镜像拉取与调度积压，是「一个静悄悄拖慢研究、烧掉训练预算的沙箱基础设施问题」；他们宣称新版把这件事加速了约 45×。官方声明（厂商博客，未独立复现）
  3. 状态污染与调度面本身会崩。 R2E-Gym 的技术报告记录了一个很具体的失败：单个 GRPO 迭代要并行起 512 个 Docker 容器（batch 64 × 8 rollouts），并发实验把上千个容器推上天，单机 Docker 的 API server 过载、daemon 最终崩溃，于是他们把环境编排搬到了 Kubernetes。论文报告 这是「不是跑个 Docker 就行」最硬的证据。
  4. 轨迹本身是产品，需要被统一采集。 Verifiers 这类库把一次 rollout 明确拆成 prompt / completion / answer / state / info 字段；AgentOhana 的工作是把异构来源的轨迹统一成同一种多轮格式再训；SWE-Gym / SWE-smith / R2E-Gym 的价值主张都是「可执行环境中批量合成的任务 + 成功轨迹」。论文/官方文档 换句话说：没有轨迹 schema，就没有后训练。
  5. 安全边界变硬了。 当 agent 自动生成并执行未经人审的代码，容器逃逸不再是理论风险：Docker 默认的 runc 共享宿主内核，一次内核提权就等于拿到同机所有容器；Firecracker 用 KVM 做硬件隔离（约 100–200 ms 启动、每 microVM 内存开销 <5 MiB），gVisor 用用户态内核重实现 syscall 面，Kata 则把 microVM 包装成标准容器 API。厂商技术博客（第三方横向评测）

1.2 反面：为什么「跑个 Docker」不够

把上面五条合起来看，「沙箱基础设施」这个词其实指四件互相耦合的事，缺一件就不成立：

① 生命周期（reset / snapshot）

一次 rollout 之后环境必须回到确定状态，否则第二条轨迹被第一条污染。OSWorld 的 DesktopEnv 直接照 Gym 的写法：__init__ → reset(task_config) → step → evaluate → cleanup，并管理 VM 快照。文档/二手整理

② 并发（pool / 冷启动预算）

池化、预热镜像、按需扩容。这一层决定了「每小时能产出多少条轨迹」，也就是单位数据成本。

③ 可验证性（verifier 契约）

环境必须能回答「这个任务成功了吗」，且答案是可复算的（脚本/断言），不是 LLM 打分。直接证据

④ 留痕（trajectory / artifact）

每一步的 action、observation、工具返回、最终产物都要落盘，并且和「哪个环境版本、哪个语料版本」绑定。

研究者的读法（推断，非任何单一来源的原文）：这四件事的共性成本是「状态的边界要显式声明」。一旦你把「哪些是只读输入、哪些是可写产物、哪些是外部副作用、时钟从哪来」写进配置，你就同时拿到了隔离、复现和可验证性。规模只是把这套声明复制一万份。这正是小项目能借的部分——借声明方式，不借复制机器。

5. 可借用清单 P0 / P1 / P2

5.1 P0：不做就无法声称「可复现」（期中 demo 前必须全绿）

  • 每任务/每语料一个容器——不是每次 ingest 一个进程。语料 = 环境，环境 = 容器。这样「语料版本」和「运行记录」天然一对多。
  • corpus 只读挂载：-v $PWD/corpus/Victoria_Subset:/home/victoria:ro。只读是防自己：pipeline 里任何一次误写都会毁掉「同一份输入」的前提。
  • workspace 可写覆盖层：--tmpfs /workspace:rw,noexec,nosuid,size=2g，退出即消失。要留下的东西显式写到 /data。
  • 固定 mtime / 时区：TZ=Asia/Shanghai + 构建期把语料 mtime 归一（find … -exec touch -t 202001010000 {} +），否则「按时间排序」「最近修改」类问答每次结果不同。
  • 网络出口白名单或 --network none。我们的 pipeline 要调 LLM API，所以采用两段式：容器内 deterministic 部分 --network none；LLM 调用走 host 侧 proxy，并把 request/response 写进 artifacts/llm/ 做 replay。这是从「在 proxy 网关处捕获推理、让黑盒应用可训练」这一思路借来的（见 §8 中 NeurIPS 2026 那条）。推断性设计
  • 产物与轨迹落盘：-v $PWD/artifacts/runs/$RUN_ID:/data:rw，至少四个文件：manifest.json、trace.jsonl、evidence.json、report.md。
  • 一次性 _test DB：每次运行建 graph_${RUN_ID}_test，跑完不删（存档）但下次绝不复用。_test 后缀让「这只是实验库」在名字上就成立。

5.2 P1：让报告从「跑通了」升级到「可审计」（期末前）

  • 快照 / 重置 → 把「增量摄入」做成 wave 序列。不要真去实现快照 API，用目录当快照：corpus/W0/（原始 137 文件）→ W1/（+12 文件）→ W2/（改 3 个文件版本）→ W3/（删 2 个）。每个 wave 跑一次增量 ingest，第 4 次跑「全量重建」做对照。这是整个报告里最有解释力的一张图。
  • Verifier 钩子（三类断言，正好对应我们图谱的三类边）：
    • 版本断言：file F 的 version v2 是否指向 v1，且 v1 仍在库；
    • 项目归属断言：entity E 是否属于 project P，且 P 的成员集合闭包正确；
    • 引用断言：答案里的每个 claim 是否有 ≥1 条 evidence 边指向真实存在的文件路径 + 行/页码。
    引用断言是最值钱的一条：它把「幻觉」变成可计算的失败率。
  • 并行跑 11 道 QA 或 3 个条件：docker compose run --rm runner --condition graph，三个终端或 --scale。注意 R2E-Gym 的教训：并发数是有限资源，11 个容器 ok，别在 CI 里开 100 个。
  • 成本记账：manifest.json 里记 wall_clock_s、cpu_s、input_tokens、output_tokens、llm_cost_cny。别人问「你这套要多少钱」时，答案应该来自文件而不是估算。

硬规则（写进 README，不写进「注意事项」）：

  • 永不挂 $HOME。个人文件系统是数据集，不是你的家目录；一次 rm -rf 就没了。
  • 永不挂 /var/run/docker.sock。挂了等于把宿主机 root 交给容器内的任何代码。
  • 永不 --privileged，永不 --network host。
  • 语料只读；需要修改就复制到 /workspace 再改。
  • 镜像里不放语料、不放密钥：语料走挂载，密钥走运行时 env。
  • 镜像按 digest 固定（image@sha256:…），不用 latest。

6.2 期中 demo 的最小版：一条 docker run

# 一次性运行：只读语料 + tmpfs 工作区 + 无网络 + 非 root + 无 capability
RUN_ID=$(date +%Y%m%dT%H%M%S)__graph__seed0
mkdir -p "artifacts/runs/$RUN_ID"

docker run --rm \
  --name "pcmem-$RUN_ID" \
  --user 1000:1000 \
  --read-only \
  --tmpfs /tmp:rw,noexec,nosuid,size=256m \
  --tmpfs /workspace:rw,noexec,nosuid,size=2g \
  --cap-drop ALL \
  --security-opt no-new-privileges \
  --pids-limit 256 \
  --memory 2g --cpus 2 \
  --network none \
  -e TZ=Asia/Shanghai \
  -e RUN_ID="$RUN_ID" \
  -e CONDITION=graph \
  -e SEED=0 \
  -v "$PWD/corpus/Victoria_Subset:/home/victoria:ro" \
  -v "$PWD/artifacts/runs/$RUN_ID:/data:rw" \
  pcmem/pj01@sha256:PUT_YOUR_DIGEST_HERE \
  python -m poc.run --condition graph --seed 0
矛盾点必须显式处理（别在答辩时被问倒）：--network none 与「调用 LLM API」互斥。 两种合法解法：(a) 容器内只做 deterministic 部分，LLM 调用通过 --add-host/proxy 走 host 侧白名单代理，并把问答对落到 artifacts/llm/，重跑时优先 replay；(b) 准备一组缓存的 fixture 响应，做「离线可复现模式」。 推荐 (a)+(b) 同时有：默认离线 replay 出确定性结果，另跑一遍在线模式验证「换一个模型会怎样」。

7. 成本与时间量级

先说道歉：下面的数字是量级估算，不是报价。所有单价来自 2026 年 11 月检索到的公开页面（含第三方汇总），未逐条打开官方计费页核对；云厂商促销价每周变化。请把区间当「数量级」，不要当预算表。

7.1 假设（写清楚，才能被质疑）

  • 单次运行 = 解析 137 文件（无 OCR、无视频抽帧）+ 建图 + 11 道 QA 检索与作答。
  • 语料体量按 137 文件 ≈ 150–300 MB 估（含图片/音频）；1000 文件按线性放大 7×，但我给 3× 的宽放，因为固定开销（模型加载、依赖导入）不随文件数增长。
  • CPU 侧：本地 embedding（小模型，CPU 推理）约 50–200 chunk/s；PDF/Office 解析是主要 CPU 消耗。
  • 笔记本整机功耗按 40–60 W 计，电价 0.6 元/kWh。
  • 云主机：阿里云 2 vCPU / 4 GiB 按量付费约 0.33–0.39 元/小时（多个 2026 年页面给出的区间；实际以控制台为准）。
  • 托管 sandbox：按 2 vCPU / 2 GiB 计，E2B 级单价约 $0.0504/vCPU·h + $0.0162/GiB·h → 约 0.9–1.0 元/小时；Modal 级约 1.3–1.4 元/小时（第三方计算器汇总，币种按 1 USD ≈ 7.2 CNY）。
  • LLM 调用：按每题 3 次检索-作答循环、约 40–80k tokens 往返估。

7.3 三条结论

  1. 沙箱成本是四舍五入误差，token 成本才是主项。单次 137 文件运行：算力 0.05–6 元（2C4G 到 16C32G），LLM 3–8 元（悲观上限 20–60），仍高一个量级。推断（基于上表假设的算术） 所以不要为了省算力去优化沙箱；要为了「少跑无效实验」去优化可复现性——每省下一次重跑，省的是 3–8 元（悲观 20–60）。
  2. 本机 vs 云主机：本机赢在边际成本，云主机赢在「环境一致」。本机跑一次约等于零元，但「在我机器上能跑」不是可复现。云主机的真正价值不是算力，而是一台干净的、可以整机重装的机器——它把「环境漂移」这个变量消掉了。量级上：云主机一天 8–10 元，比一杯咖啡便宜。推断
  3. 迭代次数决定该买什么。一天跑 ≤5 次 → 本机；一天跑 10–50 次 → 租一台常驻云主机（包日/包月）；一天跑 >200 次 → 才轮到按秒计费的托管 sandbox（那时你已经有并发需求了）。我们大概在第一种。推断

8. 边界：沙箱不保证什么

8.1 沙箱只保证两件事

隔离（这次运行碰不到别的）和复现（同样的输入 + 同样的镜像 → 同样的执行路径）。它不产生任何语义。特别地，它不会自动带来：

表 9：沙箱给不了的标注。这些必须我们自己造——也正好是本项目的学术贡献所在。
我们需要的标注沙箱给吗真实来源怎么补
版本链（同一文档的 v1→v2→v3）不给。文件系统只有 mtime，没有「谁取代谁」内容相似度 + 文件名模式 + 显式 diff 证据建 supersedes 边，并在 verifier 里断言「v2 存在时 v1 不被当作 current」
项目归属（文件 → 项目/客户/课程）不给。目录结构只是弱信号路径 + 共现 + 时间窗 + 内容实体建 belongs_to 边，用「同项目文件的检索召回率」当指标
引用边（答案 → 具体文件/页/行）不给。容器只保证文件还在检索打分 + 原文 span每条 claim 强制带 (path, locator)，verifier 检查路径存在且 span 命中关键词
增量刷新（新增文件后图谱如何变）不给。tmpfs 一退全没wave 序列 + 前后图谱 diff每个 wave 存图谱 dump，期末报告核心图 = wave × (节点, 边, 错误率)
个人画像 / 偏好不给。沙箱没有「用户」行为轨迹（FileGram 的思路）把 mtime 序列、目录移动、打开顺序当作弱标签

8.2 三个必须写进报告的风险

  1. 许可：HippoCamp 是 research license，原始文件不可再分发。HippoCamp Research License v1.0 的授权范围限定为「非商业研究、benchmark 与评测」，并且是「有限、非独占、不可转让、不可再许可、可撤销」的。直接证据（LICENSE 原文摘要） 实操后果：
    • 语料不进 git、不进镜像层、不进公开的 artifact 包；只以挂载方式进入容器。
    • 报告里贴文件片段要谨慎；贴路径树可以，贴内容要打码或只贴最小必要片段。
    • 不把语料上传到任何托管 sandbox（那既是再分发，也是数据出境）。
  2. 官方评测设置要求隐藏 gold。HippoCamp README 明确：默认 raw-file 设置下，JSON 标注（题目/答案/证据/诊断）、HippoCamp_Gold/、viewer parquet 都不应暴露给被评测的 agent，应在评测结束后再解封。直接证据 工程后果：gold 目录不能和 corpus 一起挂进同一个容器——否则「只读挂载」也挡不住 agent 直接读答案。我们的做法：corpus/（agent 可见，ro）与 gold/（只挂给 verifier，ro）分离，两个容器两个挂载集。
  3. 托管 sandbox 的 vendor lock-in 与数据出境。一旦把 pipeline 写成「调用某家的 sandbox SDK」，环境定义、快照格式、日志格式都绑定到该厂商；迁移成本落在最不该花时间的地方。加上语料是个人电脑文件（即便是合成 persona），出境涉及合规解释成本。推断（基于许可条款与产品形态）

8.3 沙箱也治不好的复现性问题

  • LLM 非确定性：temperature=0 也不是 bitwise 确定（后端批处理、版本升级都会变）。→ 记录 model_id + prompt_hash + 响应缓存。
  • Embedding / 解析库版本漂移：torch、pdfplumber、tokenizer 换小版本，向量就变。→ 镜像 digest 固定 + 在 manifest 里记 pip freeze 的 hash。
  • 图谱构建顺序：并发写图 → 边 id 不稳定。→ 单线程构建，或按 (src, rel, dst) 排序后落库。
  • 时间依赖：相对时间问句（「上周」「上个月」）在固定 TZ 之外还需要固定「now」。→ 注入 FAKE_NOW 环境变量，禁止代码里调 datetime.now()（用 lint 规则挡）。

10. 如果只做一件事，做什么

做「一次运行 = 一个不可变指纹 + 一条可验证证据链」这件事。

具体是：把 corpus/Victoria_Subset 以 :ro 挂到一个 --network none --read-only --cap-drop ALL --user 1000:1000 的容器里的 /home/victoria，跑完 ingest → graph → 11 题 QA，然后逼自己在 artifacts/runs/<id>/ 里只留下四样东西：manifest.json（语料 hash / 镜像 digest / 代码 commit / 模型 id / prompt hash）、trace.jsonl（每步一行）、evidence.json（每条答案 → 文件路径 + 定位符）、report.md（人读的结论）。

理由：这四样东西同时买到三件别人要花一个季度才能买到的东西——可复现（指纹可重算）、可评分（证据可断言）、可增量（换一个 wave 目录就是新环境，指纹自然变化）。而它不需要 K8s、不需要 microVM、不需要任何账号，一个下午能做完。

本报告为课程项目 pj01（选题 1：帮助 Agent 的全 PC 文件管理记忆系统，PC-Mem）的前置调研。所有外部论断按「官方 / 论文 / 推断」标注；未验证项集中在 §9.4。报告本身不含任何 HippoCamp 原始数据。

写作方式说明：结构、表格归类、P0/P1/P2 分级、成本算术与「如果只做一件事」为作者归纳；§9 中逐条标注了证据类型与核实程度。
